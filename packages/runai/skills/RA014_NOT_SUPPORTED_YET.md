name: RA014_NOT_SUPPORTED_YET
description: Valid syntax this milestone cannot compile — an unsupported construct, import, unreachable value, `declare`, or reserved name.

## What it means

The parser accepted this file: this is a limitation of the compiler, not a syntax error. It covers five families. A first is a JSX construct this milestone cannot lower (a component tag, a spread, a fragment root, and so on), where lowering reports the construct instead of dropping it, because markup emitted without part of a node is wrong in a way nothing reports. That first family also covers four emit-time shapes whose output would differ by mode or not parse: children inside a void element, a duplicate attribute, an early `return` before the route's JSX return, and an `async` or generator route component. It also covers markup the HTML parser would reshape, so the emitted HTML text re-parses into a different tree than was written: a `<p>` holding a block-level element, a tag that closes an open element of its own kind, a child outside its parent's content model or bare text outside a table cell, an `<a>` inside an `<a>` or a `<form>` inside a `<form>`, a list item with no list, a tag the parser only builds under one parent, and — in an island — a dynamic binding inside a text-only element, where the marker the island needs is swallowed as text. A second is a module the emitted file cannot resolve or write: an `import` or re-export of a module other than `"runai"` has no bundler, a default or namespace import of `"runai"` is not a form the client module emits, and `import x = require(…)` or `export =` is rewritten by type stripping into `require`/`module.exports`, which an ES module does not have — each route is emitted from its own file, so a second module cannot be resolved or inlined. A re-export is refused even when its source is `"runai"`, because the emitted module never carries one, so accepting it would drop the statement silently. A third is a value the generated module cannot see — a `"runai"` name or the route component's own name at module scope, in a component-body statement, or in a `"use static"` route's markup, whose prerender module has no imports and does not declare the component, or the route's own parameter there, which the prerender call supplies with nothing, or at module scope, where no emitter declares it. A module-level declaration is *not* in this family: module-scope statements are emitted above the component. Neither is a component-body statement's own local, which is emitted inside the component. A `declare` statement is refused: it is the fourth family, because type stripping erases it before the route is emitted, so the binding it introduces never exists in the generated module — a route file defines the values it names. A fifth is the emitted module's own names: a declaration, export name, or reference to `_esc`, `_attr`, or `render` is refused because the generated module declares those itself.

## Why it is an error

`RA014` is what the compiler reports when the file parses but this milestone cannot compile it: each refusal is a limitation of the compiler, not a syntax error. The code covers five families, and each would be wrong silently rather than loudly.

The first is the JSX constructs it refuses: a capitalized tag or member-expression tag (component inlining comes with a later plan), the runtime's own `<For>`/`<Show>`/`<When>` primitives (their lowering comes with a later plan and is not component inlining), a namespaced tag, a `<this>` tag, JSX inside a `{…}` expression, a JSX-valued attribute, a spread attribute or child, a fragment as the returned root, a second JSX return, JSX in any other route body statement, and JSX in a module-level statement of a route file. Each would either drop part of a node or copy JSX into a JavaScript module where it cannot parse. Module-level JSX is refused only in a file that has a route: a `.tsx` file with no default export is a component module, and a helper there may legitimately hold module-level JSX. The plan's later milestones lift these one slice at a time. Four emit-time shapes join this same first family because the artifact they would produce is wrong rather than merely unsupported: children inside a void element, which the HTML parser would move outside it; a duplicate attribute, which a prerendered page would resolve to the first value and a hydrated island to the last; an early `return` before the route's JSX return, which `render()` cannot carry because it returns one string; and an `async` or generator route component: both modes call the component synchronously and use its return value, so a generator route component's iterator and an `async` one's promise are not the markup either mode inserts.

A further group inside that first family is markup the HTML parser would **reshape**, so an island's emitted HTML text re-parses into a different tree than the author wrote and a marker would address the wrong node. Each is refused rather than emitted, and the `message` names the parent, the child, what the parser does, and the repair: a `<p>` containing a block-level element, which closes the paragraph so the child becomes a sibling; a tag that **closes an open element of its own kind** (`<li>` in `<li>`, `<p>` in `<p>`, `<tr>` in `<tr>`, `<td>`/`<th>` in either, any heading in any other, `<button>`, `<option>`/`<optgroup>`, `<a>`, `<nobr>`); a child that violates its parent's **content model** (`<table>` holding anything but its table parts, `<ul>`/`<ol>`/`<menu>` anything but `<li>`, `<dl>` anything but `<dt>`/`<dd>`/`<div>`, and so on), or bare text fostered out of a table family element; an `<a>` inside an `<a>` or a `<form>` inside a `<form>`; an `<li>`/`<dt>`/`<dd>` with no list to belong to; a tag the parser only builds under one parent (`<td>` outside `<tr>`, `<option>` outside `<select>`, `<figcaption>` outside `<figure>`, …); and, in an island, a dynamic binding inside a text-only element (`<script>`, `<style>`, `<title>`, `<textarea>`, `<noscript>`, …), where the `<!>` marker the emitter needs is swallowed as text. The repair is to move the child to where its content model allows it, or to write the value as static text or on a sibling element that holds normal content.

An import or re-export the emitted module cannot resolve or write is the second family, refused for one of three reasons. A module other than `"runai"` has no bundler yet: each route is emitted from its own file's text, so a second module can be neither resolved nor inlined, and the emitted module would not load. The same holds for a re-export (`export … from "./x"`, `export * from "./x"`): the emitted file writes one import or none, so the statement names a module nothing resolves. This lifts when bundling lands. A re-export whose source *is* `"runai"` is refused for a different reason — the statement is never emitted, so accepting it would drop the author's statement with no diagnostic — and the repair is `import { owner } from "runai"`, then use or export the written binding. A default (`import runai from "runai"`) or namespace (`import * as runai from "runai"`) import of `"runai"` is refused because the island emitter writes exactly one import, merging the route's named specifiers only; the repair is to rewrite the declaration as named imports. And the CommonJS spellings TypeScript allows — `import x = require("./x")` and `export = x` — are refused because type stripping rewrites them to `require(…)` and `module.exports = …`, which an ES module does not have. `import type` — and the inline `import { type X }` form — is exempt, because types are stripped and leave no runtime import behind.

The third family is a value the generated module genuinely cannot see, and it has two members only. A `"runai"` name, or the route component's own name, used at module scope, in a component-body statement, or in a `"use static"` route's markup is refused because the prerender module contains no imports and does not declare the component, so the repair is the directive, `"use island"`. The route's own parameter in a `"use static"` route is refused because `render()` takes no arguments, so `{props}` or `const x = props` would be `undefined` at build time; at **module scope** it is refused in an island too, because no emitter declares the parameter there either. A module-level declaration is deliberately **not** in this family: module-scope statements are copied into the emitted module above the component (design §7.6 expects module-level state — "module-scope signals are per-island too, since each island is its own module instance"), so a module-level `const` the markup names is reachable. A component-body statement's own local is not in this family either: the statement is copied into the component, so the local exists there.

A `declare` statement is the fourth family: it is erased before emission, so the binding it introduces never exists in the generated module, and a route file cannot declare a binding it does not define.

The parameter list itself is a **shape** the emitters rebuild rather than copy: both write the component as `function <Name>(props)`, so a default, a destructuring pattern, a rest parameter, or a different name is dropped, and everything it binds does not exist in the artifact. That is why `props: P = owner` is refused in an island where `owner` is otherwise a real name — the defect is the dropped signature, not the reference.

The fifth family is the generated module's own **reserved** names: `_esc`, `_attr`, and `render`. A declaration, export name, or reference to one of them is refused because the emitted module declares those names itself, so a route binding would shadow a helper the template calls or export `render` twice. A `var` makes this sharper than a name scan suggests: it hoists to the route body's own function scope, which is the scope the emitter copies into `render()`, so a `var` in a nested block, a `for` init, or a `try`/`catch` reaches the template's call site even though it is not written at the top of the body.

An attribute with an empty expression (`name={}`) is deliberately **not** on this list: that is a parse error, reported as `RA007`, not valid syntax waiting for a later milestone.

## Fix

For an import or re-export, inline the value or import it from `"runai"`; a re-export whose source is `"runai"` becomes `import { owner } from "runai"` with the name used or exported here; a default or namespace `"runai"` import is not a form the emitted module writes, so rewrite it as named imports; write `import x = require(…)` as an `import`, and `export =` as `export default` or a named export. For a `declare` statement, replace it with a value this file defines, because it is erased before emission. For a route signature — a default, a destructuring pattern, a rest parameter, or a different name — the emitters rebuild the parameter list as one `props` parameter, so write the parameter as `(props: Record<never, never>)` when it carries no data, or with the type it actually needs, and read the fields from `props`. For a value the generated module cannot see — a `"runai"` name, or the route's own component, at module scope, in a component-body statement, or in a `"use static"` route's markup, or the route's own parameter in a `"use static"` route — do what the message names: change the directive to `"use island"` for the first two, and replace the parameter reference with a literal value. For a JSX construct, write the spread out, move the JSX into the children or the returned tree, give the attribute or prop a value, wrap a root fragment in one parent element, render a runtime primitive's markup directly, or keep exactly one JSX return. For children inside a void element, move them out of it or use an element that accepts children. For a duplicate attribute, keep exactly one of them, because a prerendered page keeps the first value and a hydrated island keeps the last. For an early `return` before the route's JSX return, return one element from the component: `render()` returns one string, so the body cannot exit early. For an `async` or generator route component, remove the modifier and return the markup directly, because both modes call the component synchronously. For a declaration, export name, or reference that uses a reserved generated name (`_esc`, `_attr`, or `render`), rename it, because the emitted module declares those names itself.
